## 이어진 세션 — F07 페이지 통합 (2026-09-30, 같은 날 후속)

이전 세션은 F07의 헬퍼(`resolveRegionIdentity`, `getCachedRegionCandidatesBySlug`)만 준비하고
실제 페이지 3곳은 통합하지 않은 채로 `NOT_RUN`으로 남겼다. 이번 세션에서 최소 변경으로 통합했다.

### 변경 내용

- `lib/db-queries.ts`: `getCachedResolvedRegion(sigunguSlug)` 신설. 내부적으로
  `getCachedRegionCandidatesBySlug` + `resolveRegionIdentity`를 호출해, slug가 모호하면
  (서울/부산 강서구 등) 임의의 첫 행 대신 `undefined`를 반환한다. 기존 deprecated
  `getCachedRegionBySlug`는 그대로 남겨두었다(다른 호출부가 없는지 확인 후 향후 제거 검토).
- `app/shelter/[sigungu]/page.tsx`, `app/[sigungu]/[type]/page.tsx`,
  `app/[sigungu]/[type]/[slug]/page.tsx`: `getCachedRegionBySlug` 호출을
  `getCachedResolvedRegion`으로 교체. 각 페이지가 이미 갖고 있던 `region?.xxx ?? slug` 폴백
  패턴은 그대로 활용되므로, ambiguous일 때 `region`이 `undefined`가 되어 안전한 기존 폴백
  경로로 흐른다. **URL 구조(시도 접두 slug 등)는 변경하지 않았다** — 문서 8.2가 이를 별도
  승인 대상으로 명시했기 때문.
  - `shelter/[sigungu]/page.tsx`는 `region`이 없으면 `notFound()`를 호출하는 기존 로직을
    유지한다. 이는 실제 유입이 있는 gimpo/ganghwa/nowon 등 unique slug에는 영향이 없고,
    모호한 slug(예: gangseo)에서는 "잘못된 시도의 목록을 보여주는 것"보다 안전한 선택이다.
  - `[sigungu]/[type]/page.tsx`, `[sigungu]/[type]/[slug]/page.tsx`는 이미 `region` 없이도
    동작하도록 설계되어 있어(slug 문자열 자체로 폴백) 동작 변경이 없다.
