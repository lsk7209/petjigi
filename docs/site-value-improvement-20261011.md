## 출처와 범위

응급·검진 문서는 연결한 수의학 1차 자료의 범위를 설명하고 실제 판단은 담당 수의사에게 연결한다. 보험 문서는 국내 법령과 보험사 약관·청구 안내를 구분한다. 특정 보험사의 예시는 모든 상품의 공통 규칙이나 추천이 아니다. 청구 서류를 사이트 문의처로 보내도록 유도하지 않는다. 문서별 출처는 해당 시드 본문과 sources에 있다.

## 반영·복구 경계

현재 변경 본문 해시와 보호 메타데이터 검사는 `site-value-update-manifest-20261011.json`이 기준이다. 이전 `core-guides-update-manifest-20261011.json`은 앞 단계의 역사적 스냅샷이며 현재 해시를 나타내지 않는다. 합산 변경 시드 24행의 id/type/status/publishedAt/reviewer 메타데이터는 유지했다. 은퇴한 guide 청구 시드는 원본을 보존하며 운영 공개 blog와 구별한다. 실제 반영 가능한 DB 행 수는 향후 권한 있는 dry-run에서 확인해야 한다.

운영 반영 시 전체 seed를 실행하지 말고 안전한 선택 업데이트 스크립트의 dry-run, 행 ID·상태·백업·동시 수정 검사를 검토해야 한다. 스크립트의 허용 필드는 본문·설명·출처·고지·수정일과 제목·검색 제목이며 발행·검토 메타데이터는 변경하지 않는다. 반영 및 배포 뒤 공개 내용·경로·입력·인쇄를 다시 검사해야 한다.

새 적용 백업은 7개 필드 전체가 현재 DB 값과 같아야 한다. 과거 3개·5개 필드 백업 또는 오래된 백업이 같은 파일명으로 있으면 덮어쓰지 않고 `skip_backup_conflict`로 중단한다. 과거 백업을 복구할 때 없는 제목 필드는 현행 값을 유지한다. 프로세스 종료 코드만으로 전 행 성공을 판단하지 말고 각 행의 결과를 확인해야 한다.

외부 남은 작업: 이메일 DNS/수신·모니터링 확인, 권한 있는 운영 DB 반영·배포, 배포 후 재검사, AdSense 계정 상태 확인. 승인 가능성을 보장하는 수치나 결론은 제시하지 않는다.
